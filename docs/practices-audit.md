# Common-base practices audit

- **Repo:** `enterprise-knowledge-base`
- **Catalog id:** Hrz2 (package `enterprise_kb`, env prefix `KB`)
- **Authoritative source:** reconciled locally; the maintainer's
  cross-repository audit matrix is updated separately.
- **Catalogue reference:** [`common-base-practices.md`](https://github.com/portable-genai/.github/blob/main/common-base-practices.md) (checks A1..G7)
- **Note:** Every check below was re-run against the current tree (grep + file reads +
  running the offline gate), not assumed. This is the first audit of the Hrz2 row, which
  read `-` (no tracked gaps) only because it had never been audited. Hrz2 is the shared
  governed-RAG KB (the store every agent queries). It DOES run a generative LLM (the
  grounded `answer()` path synthesises + self-critiques over retrieved passages), so the
  `[agentic]` checks apply and are scored on the merits, not marked N-A.

Applicability: Hrz2 ships a UI (`ui/`) and Terraform (`infra/terraform/`), so `[ui]` and
`[infra]` checks apply. **Load-bearing** checks (a FAIL breaks a shared catalog guarantee)
are A1-A6, C1-C5, D1-D3 and E1. Evidence: the full `make test` offline suite passes on the
locked dev environment with no Google Cloud SDK, the eval gate is green (14 golden examples, including three that
plant synthetic PII), `terraform fmt`/`validate` are clean offline, and `ruff check`,
`ruff format --check` and `mypy src` are clean.

The gcp
`AccessControlPort` performs the tenant-scoped, parameterized AlloyDB binding query and has
offline integration-style coverage for tenant isolation, enabled-only mapping, parameter
binding, input normalization, database failure propagation and identifier validation. The
incomplete-managed-operation ledger is empty only after those tests. Hrz2 now re-exports the
shared `Principal` from `hex-service-kit`, whose request scope is narrow-only and
fail-closed. Recursive Python and UI scanners cover every shipped source and are mutation-proved
against default-bearing reads. The governed-RAG remote surface is versioned and discoverable.
The same audit found and closed a live-authentication gap in the existing AlloyDB seam. All three
adapters now share a fail-closed connection validator and enable connector IAM auth. Terraform
creates distinct IAM database users for the app and pipeline and grants each active service
account only client, database-login and service-usage permissions; disabled Agent Runtime gets no
identity or dormant grant. No database password or secret payload enters Terraform state. A
protected VPC-reachable schema-migration workflow applies the reviewed bootstrap/migration under
the dedicated IAM owner, revokes `PUBLIC`, grants the serving identity `SELECT`, grants only the
pipeline scoped DML, and retains hashes/preflight/grant evidence.
Managed readiness checks the instance URI and workload IAM username before serving.

Layout-aware parsing, the
anchor model, the `CitationStorePort` (gcp / local / onprem) and deterministic
claim-to-anchor resolution are in place, and the `citation_accuracy` eval gate is set
at anchor level (0.98) against an independent golden-anchor oracle, raised from page level (0.90).
No check is regressed: the affected rows are B2 (locator precision, above), B4 (the new
`policy.citation.anchor_match_floor` is config with the reference value as its default),
B5 (`BlockKind` is a `StrEnum` in the kernel), C2 (the new port is tenant-scoped and
fail-closed, with a cross-tenant denial test proven RED without the scoping) and E2 (the
raised metric is proven able to go red by `self_check`, including a tautology guard that
scores the same passage against a wrong-but-real block of the same document).

The C2 gaps (any-of matching, missing tenant
partition, client-widenable `acl_principals`) are closed, and an adversarial re-review that
followed the read-path fix hardened the tenant partition across the write path (delete /
re-ingest), the production GCP ingest adapter, the freshness ledger + `corpus/status`, and
the IAP identity fallback: see the C2 row.
